# Week 2 공적 근거 기반 매물 브리핑 업무 시스템

## 한 문장 목표

매도 의뢰 자료를 비식별 Google Drive 폴더에서 받아 Codex가 Skill·Plugin·MCP로 교차검증하고, 매수 목적별 제안서와 내부 검수표를 만든 뒤 사람 승인·비공개 DB 저장·비식별 사례 기록까지 연결한다.

## 구현 범위

| 영역 | 구현 위치 | 역할 |
|---|---|---|
| 반복 절차 | `.agents/skills/property-briefing` | 자료 우선순위, 상태 구분, 출력 계약, 파일럿 검수 |
| 비공개 업무 화면 | `apps/property-briefing-private` | 케이스 입력, 근거·임대차 대조, 결과 분리, 승인, 타이머 |
| 비공개 DB 브리지 | `apps/property-briefing-private/integrations/google-apps-script/Code.gs` | 별도 Google Sheet 저장·조회·공개 요약 생성 |
| 공개 요약 API | `api/week2-summary.js` | 읽기 비밀값을 서버에서만 사용하고 허용목록 반환 |
| 공개 실용보드 | `output/study-dashboard` | 승인된 비식별 수치와 배운 점만 표시 |

## 재사용 가능한 목적 프로필

- 매물마다 `주요 매수 목적 1개`와 선택적인 `보조 매수 목적 1개`를 고른다.
- 지원 목적은 `임대수익 / 자산가치 / 직접사용 / 개발·리모델링 검토 / 장기보유 / 기타`다.
- 임대수익형은 계약별 임대차 대조, 합계, 공실과 두 종류의 기초 수익률을 우선한다.
- 자산가치형은 현재 입지와 공식 개발·교통계획을 분리하고 `현재 확인 / 계획 반영 / 추진 중 / 추가 확인 필요`로 사업 단계를 표시한다.
- 둘빌딩은 `주목적: 임대수익`, `보조목적: 자산가치` 조합을 검증하는 첫 파일럿이다. 시스템은 새 케이스에서도 같은 선택·검증·출력 흐름을 재사용한다.

## 데이터 레코드

- `Case`: 매물 유형, 거래 유형, 비공개 주소·매도가, 주목적·보조목적, 마스킹 폴더 ID, 동의 범위와 상태
- `SourceEvidence`: 자료 종류, 원문 값, 최신 조회값, 기준일, 확인일, 차이, 상태, 대표님 판단
- `LeaseComparison`: 계약별 층·호, 설명값과 계약서의 보증금·월세·기간, 판독·검수 상태
- `ReviewGate`: 입력·마스킹, 교차검증, 고객용·내부용 분리의 순차 승인
- `TimerEntry`: Before/After, 업무 단계, 활동시간, 대기시간 제외 여부, 수정 횟수
- `EvidenceLog`: Codex 실행과 검수의 화면 증거용 단계 기록
- `PublicationSummary`: 주소·고객·임차인·계약서·비공개 링크를 제외한 공개 허용목록

## 상태 계약

- `확인됨`: 제공 원문과 공식 근거의 해당 값이 일치하거나 검수 완료
- `불일치`: 비교 가능한 값이 서로 다름
- `자료 없음`: 필요한 자료 또는 값이 제공되지 않음
- `추가 확인 필요`: 자료는 있으나 사람 판단이나 추가 공식 조회가 필요함
- `기준일 경과`: 자료 기준일이 현재 판단에 쓰기 어려움
- `판독 불가`: 사진 품질, 페이지 누락 등으로 읽을 수 없음

충돌은 최신값으로 덮어쓰지 않는다. `원문 값 / 최신 조회값 / 기준일 / 확인일 / 차이 / 대표님 판단`을 동시에 보존한다.

## 수익률 표시 계약

- `매매가 기준 단순 임대수익률`: `(월세 합계 × 12) ÷ 매도가 × 100`
- `보증금 차감 투자금 기준`: `(월세 합계 × 12) ÷ (매도가 - 보증금 합계) × 100`
- 두 지표 모두 공실손실, 세금, 수선비, 관리비, 금융비용 등이 확인되지 않으면 순수익률로 표현하지 않는다.

## 안전 경계

1. 원본 Drive와 자동화용 마스킹 폴더를 분리한다.
2. 모델 API를 웹앱이 직접 호출하지 않는다. Codex가 반자동 실행의 중심이다.
3. 비공개 앱은 Vercel Authentication을 실제 검증한 뒤에만 운영 저장을 허용한다.
4. 비공개 Sheet와 Apps Script는 기존 공개 보드 DB와 분리한다.
5. 비밀값은 브라우저·Git·공개 응답에 포함하지 않는다.
6. 공개 보드는 `PublicationSummary` 허용목록 밖의 필드를 반환하지 않는다.
7. 고객용 인쇄에서 내부 메모, 주소 입력, Drive ID, 조작 버튼을 제외한다.
8. 권리 안전성, 적법성, 투자수익을 단정하거나 보장하지 않는다.

- 도메인 단위 테스트: 11개 통과
- TypeScript 검사: 통과
- Next.js 프로덕션 빌드: 통과
- 주목적·보조목적 선택과 두 수익률 화면: 로컬 브라우저 검증 통과
- npm 취약점 감사: 수정 버전 고정 후 0건
- 전역 배포 Skills 평문 Vercel 토큰: 2개 값 제거, 프로젝트·전역 Skills 재검사 0건
- Vercel CLI: 58.4.0 및 `sachol` 로그인 확인
- Vercel 계정의 기존 토큰 폐기: 대표님 결정으로 보류
- 실제 파일럿: 둘빌딩 상가·빌딩 1건, 공적 근거 13건, 임대차 4건 입력·대조 완료
- 자료 검수 결과: 충돌 2건, 추가 확인 4건을 원문·최신값과 병렬 표시
- 사람 승인: 입력·비식별, 공적 자료·임대차 교차검증, 고객용·내부용 분리의 3단계 승인 완료
- 결과 분리: 고객용 제안서와 공인중개사 내부 검수표 작성·분리 확인
- 실측: Before 1,140분(수정 횟수 미측정), After 24분·수정 3회
- Google Sheet·Apps Script 외부 연결: 비공개 DB 저장·조회 확인
- 별도 Vercel 배포·접근 보호: 보호된 Preview 배포와 비로그인 접근 차단 확인
- 목적 프로필 변경본의 Vercel 재배포: 완료
- 공개 요약: 승인된 허용목록만 공개 실용보드에 반영하고 API 응답에서 금지 필드가 없음을 확인

## 후속 검증 항목

- 실제 Google Drive `automation-masked` 폴더 ID로 파일 입력
- 임대차계약서 PDF 1~5건을 Codex가 직접 판독하는 흐름
- 고객용 인쇄/PDF에서 주소 입력·비공개 링크·내부 메모가 제외되는지 화면 증거 보관
- 두 번째 실제 매물로 재실행하여 재사용성과 파일 판독 오류를 검증
- 발표용 12개 화면 증거 패키지 보완

첫 파일럿은 계약서 원본 PDF를 Codex가 직접 판독한 실행이 아니다. 대표님이 원본을 확인해 제공한 계약 조건을 구조화·대조했으므로, `PDF 자동 판독 오류 0건`으로 해석하거나 발표하지 않는다.
