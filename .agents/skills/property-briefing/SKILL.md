# Property Briefing

마스킹된 자료만 사용해 근거 중심 매물 브리핑을 작성한다. AI가 권리 안전성, 적법성, 개발 가능성 또는 투자수익을 확정하지 않도록 사람 승인 단계를 지킨다.

## 시작 전에

1. 실행 모드를 먼저 확인한다.
   - `실제 사건 모드`: 실제 업무용 비식별 자료를 처리한다.
   - `비식별 샘플 테스트 모드`: 명시적으로 가상·교육용인 자료만 외부 조회 없이 조건부 초안으로 시험한다.
2. 실제 사건 모드에서는 사용자가 지정한 `automation-masked` Drive 폴더만 찾는다.
3. 원본 폴더, 소유자 실명, 연락처, 주민등록번호, 계좌번호, 서명은 읽거나 출력하지 않는다.
4. 실제 사건 모드에서 다음 필수값을 확인한다.
   - `case_id`
   - 거래 유형과 매도 희망가
   - 매물 대분류와 세부유형
   - 주요 매수 목적과 선택적 보조 매수 목적
   - 주소
   - 동의 확인일과 범위
5. 샘플 테스트 모드에서는 `case_id`를 `sample-YYYYMMDD-순번`으로 만들고 모든 결과 상단에 `가상 샘플·미검증·고객 제공 금지`를 표시한다.
6. 매수 목적 표현이 자유문이면 가장 가까운 `임대수익 / 자산가치 / 직접사용 / 법인사옥 / 개발·리모델링 검토 / 장기보유 / 기타`로 제안한다. 목적이 둘 이상이면 `주목적 1개 + 보조목적 1개`로 분리하고, 사용자가 확정하기 전에는 원문과 제안값을 함께 남긴다.
7. 자료 목록, 파일 형식, 기준일, 페이지 수, 중복·누락·판독 가능 여부를 먼저 표로 만든다.
8. `references/source-policy.md`와 `references/output-contract.md`를 읽는다.
9. 선택한 매물 유형에 맞춰 `references/property-types.md`를 읽는다.
10. 실제 파일럿 또는 Before/After 실험이면 `references/pilot-checklist.md`도 읽는다.

## 처리 흐름

### 1. 입력 승인

- 의뢰인 설명과 각 원문을 별도 출처로 등록한다.
- 마스킹 상태와 필수자료 목록을 보여준다.
- 판독 불가, 페이지 누락, 중복 파일은 추정하지 않는다.
- 사용자의 `입력·마스킹 승인`을 받기 전 외부 조회나 고객용 문구 작성을 시작하지 않는다.
- 승인 전 조회하지 않은 항목은 증거 상태가 아니라 실행 상태 `승인 대기` 또는 `조회 미수행`으로 기록한다.

### 2. 사실 추출과 대조

- 주소, 면적, 용도, 층수, 사용승인일, 권리관계 메모, 매도가와 임대조건을 원문별로 추출한다.
- 임대차계약서 1~5건은 층·호별로 보증금, 월세, 계약기간, 갱신·특약과 소유자 설명값을 나란히 비교한다.
- 충돌하는 값은 덮어쓰지 않고 모두 보존한다.
- 각 사실에 출처, 기준일, 확인일과 상태를 붙인다.

### 3. MCP와 공식 근거 조회

- 건축물대장 조회 전 법정동 코드를 찾고 기본개요·표제부·지역지구 등 필요한 항목만 조회한다.
- 부동산 MCP로 해당 유형의 실거래를 조회한다. 상가·빌딩은 상업업무용 실거래를 기본으로 한다.
- 용도, 광고 표현 또는 법적 쟁점이 있을 때만 국가법령정보센터에서 현행 법령을 조회한다.
- 입지·상권·교통·개발계획은 지자체, 국토교통부, 교통기관 등 공식 출처를 우선하고 확인일과 URL을 남긴다.
- 자산가치 근거는 `현재 확인 / 계획 반영 / 추진 중 / 추가 확인 필요`로 사업 단계를 구분한다. 계획 발표를 개통·완료 또는 가치상승 확정으로 바꾸지 않는다.
- MCP나 웹 조회 실패는 실행 상태 `조회 실패`로 기록하고 해당 사실의 증거 상태는 `추가 확인 필요`로 둔다. 원문 사실처럼 대체하지 않는다.

### 4. 교차검증 승인

- `원문 값 / 최신 조회값 / 기준일 / 차이 / 대표님 판단` 표를 제시한다.
- 핵심 수치, 임대차 합계, 누락자료, 기준일 경과와 불일치를 점검한다.
- 사용자의 `교차검증 승인` 전에는 검증 완료나 권리 안전성을 표현하지 않는다.

### 5. 결과물 작성

- 주목적에 맞는 핵심 고객용 제안서를 작성하고, 보조목적은 별도 보완 근거로 분리한다.
- 임대수익형은 검증된 임대차 조건과 두 수익률 지표를 우선한다. `매매가 기준 단순 임대수익률`과 `보증금 차감 투자금 기준`을 혼용하지 않는다.
- 자산가치형은 현재 입지와 공식 계획의 사업 단계를 분리하고 변동 가능성을 함께 표시한다.
- 내부 검수표와 고객용 문구를 별도 섹션으로 유지한다.
- `references/output-contract.md`의 가시성 표에 따라 고객용·내부용·공개용 필드를 구조적으로 분리한다.
- 가격은 조정 요인과 근거만 제시한다.
- 기초 수익표는 검증된 매도가, 보증금, 월세와 공실만 사용한다. 가정과 제외항목을 표시한다.
- 모든 미확인 사항을 독립 목록으로 남긴다.

### 6. 최종 승인과 기록

- 고객용 미리보기에 실명, 연락처, 원본 Drive 링크, 내부 판단 메모가 없는지 확인한다.
- 사용자의 `고객용·내부용 분리 승인` 후 승인본으로 표시한다.
- Before/After 활동시간, 수정 횟수, 발견한 충돌, 사람 검수 항목과 배운 점을 남긴다.
- 공개 기록에는 `case_id`, 비식별 유형, 시간, 단계, 수정 횟수, 검수 결과와 배운 점만 사용한다.

## 필수 표현 규칙

- 확인되지 않은 값은 다음 중 하나로 표시한다.
  - `확인됨`
  - `불일치`
  - `자료 없음`
  - `추가 확인 필요`
  - `기준일 경과`
  - `판독 불가`
- 다음 의미를 직·간접적으로 단정하지 않는다.
  - 권리관계가 안전하거나 문제가 없다는 보장
  - 적법성 또는 법적 검토 완료의 보장
  - 개발·용도변경 가능성의 확정
  - 수익성, 시세 상승 또는 투자성과의 보장
- 예를 들어 `권리상 안전합니다`, `문제없는 물건입니다`, `수익성이 확실합니다`, `반드시 개발 가능합니다`도 사용하지 않는다.
- 대신 `입력자료 기준`, `공적 원문 재확인 필요`, `대표님 최종 검수 필요`를 사용한다.

## 중단 조건

- 자동화용 마스킹 폴더가 아닌 원본 폴더만 제공됨
- 동의 범위가 확인되지 않음
- 고객용 결과에서 개인식별정보가 제거되지 않음
- 핵심 수치 계산이 원문과 맞지 않음

중단 조건이 아니면서 자료가 부족한 경우에는 가능한 범위의 조건부 초안을 만들고 부족한 자료를 명시한다.

비식별 샘플 테스트 모드는 실제 사건 중단 조건을 우회하는 용도가 아니다. 가상 자료임이 명시된 경우에만 외부 조회 없이 `가상 샘플·미검증` 조건부 결과를 만들 수 있다.
