- **문서 버전:** v1.3

## 발표 원칙

- 부동산 전문지식보다 **Codex가 업무를 어떤 순서로 처리했는지**를 설명합니다.
- AI가 정답을 판단했다고 말하지 않고, **근거·충돌·미확인을 분리하고 사람이 승인했다**고 설명합니다.
- 실제 주소, 소유자·임차인정보, 계약서 원문, Drive·Sheet·Apps Script·비공개 URL은 보여주지 않습니다.
- 시연은 저장된 실제 파일럿을 불러오되, 화면 공유 전 개인정보가 있는 1단계를 지나 **2단계 대조 화면부터 보여줍니다.**
- 발표 중에는 비공개 DB 저장·공개 요약 전송 버튼을 누르지 않습니다.
- 실측값은 동일 사례 학습효과가 포함된 파일럿 한 건의 결과이며 일반화하지 않습니다.

이번 주 수업의 핵심 기능을 쉬운 말로 설명해 보겠습니다.

**Plan 모드**는 일을 시작하기 전에 하는 설계 상담입니다. Codex가 바로 앱을 만들지 않고 기존 업무 순서, 자주 빠지는 정보, 결과물을 사용할 대상과 완료 기준을 먼저 질문했습니다.

**Goal**은 공사가 어디까지 끝나야 완성인지 적어놓은 완료 검사표입니다. 앱만 만드는 것이 아니라 실제 사례 한 건, 사람 승인, 시간과 수정 횟수, 비식별 결과 저장까지 완료 조건으로 정했습니다.

**Skill**은 우리 사무실의 업무 매뉴얼입니다. 자료 우선순위, 충돌 처리, 고객용 문구와 내부 검수 분리 규칙을 다음 매물에도 다시 사용할 수 있게 했습니다.

**Plugin**은 Google Drive 같은 외부 서비스로 들어가는 연결문입니다.

**MCP**는 건축물대장이나 실거래처럼 외부의 최신 자료를 조회하는 공식 창구라고 이해하면 쉽습니다.

그리고 **Codex는 이 도구들을 업무 순서에 맞게 움직이는 실무 진행자** 역할을 했습니다.

# 예상 질문과 답변

## 비식별 자료와 비식별 결과는 무슨 뜻인가요?

자동차 사진을 공유하기 전에 번호판을 가리는 것과 비슷합니다. 이름·연락처·계약서 원문처럼 개인을 알아볼 정보는 가리고, 업무 검증에 필요한 자료 종류·차이·상태·처리 구조만 남긴 마스킹 자료입니다.

## 실제 사건 모드인데 왜 비식별 시연이라고 하나요?

저장된 실제 파일럿을 읽기 때문에 앱에서는 실제 사건 모드입니다. 그러나 발표 화면에서는 주소·가격·원문 링크가 있는 입력 단계를 보여주지 않고, 공개 보드에는 승인된 통계와 배운 점만 전송했습니다. 실제 입력과 공개 결과를 구조적으로 분리했습니다.

## 근거 13건과 임대차 4건은 겹치나요?

측정 대상이 다릅니다. 임대차 4건은 계약별 금액·기간을 관리한 레코드입니다. 근거 13건에는 공적 자료뿐 아니라 임대차 내용을 등기·건축물대장과 대조한 4개의 교차검증 행도 포함됩니다. 하나는 계약 수, 다른 하나는 검증 근거 행 수입니다.

## 충돌 2건과 미확인 4건은 중복인가요?

중복이 아닙니다. 충돌은 상태가 `불일치`인 2건입니다. 미확인은 `기준일 경과·자료 없음·추가 확인 필요·판독 불가`를 합친 4건입니다.

## AI가 권리 안전성이나 적법성을 판단했나요?

아닙니다. Codex는 자료를 정리하고 충돌과 확인 필요 항목을 표시했습니다. 계약서 원본 확인과 고객에게 전달할 표현의 최종 승인은 공인중개사가 담당했습니다.

## Plugin과 MCP를 모두 완성해서 사용했나요?

매물 브리핑 Skill과 건축물대장·실거래 MCP 조회는 실제 흐름에 적용했습니다. Google Drive Plugin은 마스킹 입력 경로로 설계했지만 계약서 PDF 직접 판독은 다음 실험으로 남았습니다. 서울시 공식 웹 자료도 계획 단계 확인에 사용했습니다.

## 1,140분이 24분으로 줄었다고 일반화할 수 있나요?

일반화할 수 없습니다. 동일 사례를 다시 처리한 학습효과가 포함되어 있습니다. 이번 파일럿 한 건의 활동시간으로만 기록하고, 처음 보는 두 번째 매물에서 같은 기준으로 재측정할 예정입니다.

## 13건 중 확인됨인 자료도 고객에게 그대로 말해도 되나요?

아닙니다. `확인됨`은 해당 자료의 조회와 대조 상태입니다. 계획 자료는 계획 단계로 표현하고, 개별 매물의 가치상승·권리 안전성·수익을 보장하는 문장으로 바꾸지 않습니다.

## 다른 매물에도 바로 사용할 수 있나요?

업무 절차와 검수 규칙은 Skill로 재사용할 수 있습니다. 다만 실제 재사용성을 확인하려면 처음 보는 두 번째 매물과 계약서 PDF 직접 입력 실험이 필요합니다.

## 왜 고객용과 내부용을 나눴나요?

고객용에는 확인된 사실과 조건부 설명만 담고, 공부서류 충돌·계약서 원본 확인·시장 대표성처럼 공인중개사가 먼저 판단할 항목은 내부 검수표에 남기기 위해서입니다.

## 앱이 자동으로 저장하고 공개하나요?

아닙니다. 대표님이 3단계 승인 후 비공개 DB 저장과 공개 요약 전송을 각각 실행했습니다. 발표 중에는 저장·공개 버튼을 누르지 않습니다.

- 이 문서에는 실제 주소, 고객·임차인정보, 계약서 원문, Drive·Sheet·Apps Script·비공개 Vercel URL을 넣지 않습니다.
- 수정할 때는 Markdown 원본의 버전을 올린 뒤 DOCX와 PDF를 다시 생성합니다.
- v1.0부터 v1.2까지 덮어쓰거나 삭제하지 않고, v1.3을 별도 파일로 생성합니다.
- 새 버전은 전 페이지 렌더링 검수 후 사용합니다.
- 폐기할 때는 Git 파일뿐 아니라 별도 출력·공유 폴더의 PDF 복사본도 확인합니다.
- 발표 후 피드백은 확인된 내용만 기록하며 추정한 반응은 작성하지 않습니다.
