# Week 2 발표용 화면 증거 체크리스트

## 핵심 메시지

결과물 한 장보다 `입력 → 처리 → 검증 → 사람 승인 → 비공개 DB → 다음 실험`이 작동하는 원리를 보여준다.

## 캡처 순서

| 순서 | 화면 | 보여줄 핵심 | 상태 |
|---|---|---|---|
| 1 | Plan 질문과 대표님 답변 | 실제 업무에서 보증금·월세·기간 누락 문제를 발견 | 준비됨 |
| 2 | Goal과 완료 기준 | 앱 제작이 아니라 실제 사례·정확성·증거까지가 목표 | 준비됨 |
| 3 | 비공개 앱 케이스 입력 | 원본과 마스킹 폴더 분리, 동의 범위 | 실제 파일럿 필요 |
| 4 | Codex 실행 프롬프트 | Skill과 Drive·MCP를 한 흐름으로 실행 | 실제 파일럿 필요 |
| 5 | 공적 자료 충돌표 | 값을 덮어쓰지 않고 병렬 표시 | 실제 파일럿 필요 |
| 6 | 계약별 임대차 대조표 | 설명값과 계약서 보증금·월세·기간 비교 | 실제 파일럿 필요 |
| 7 | 3단계 승인 | 사람이 통제하는 지점 | 실제 파일럿 필요 |
| 8 | Before/After | 활동시간·수정 횟수와 동일 사례 한계 | 실제 파일럿 필요 |
| 9 | 고객용 인쇄 미리보기 | 내부 검수 메모가 빠지는지 확인 | 실제 파일럿 필요 |
| 10 | 비공개 Sheet DB | 케이스·근거·계약·승인·타이머 기록 | 외부 연결 승인 필요 |
| 11 | 공개 실용보드 | 승인된 비식별 결과만 전달 | 외부 연결 승인 필요 |
| 12 | 다음 실험 | 발견한 실패와 Skill 보완점 | 파일럿 후 작성 |

## 발표 중 숨겨야 할 것

- 실제 주소와 의뢰인·임차인 정보
- 원본 또는 마스킹 Drive ID와 링크
- Apps Script URL과 모든 비밀값
- Vercel 환경변수
- 계약서 원문 이미지와 서명·도장
- 브라우저 주소창·개발자도구에 노출된 민감값
