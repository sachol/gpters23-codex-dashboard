# 공적 근거를 기억하는 매물 브리핑 업무 시스템

> 상태: 구현·로컬 검증 완료, 실제 비식별 상가·빌딩 파일럿 전 초안

## 소개

매도 의뢰를 받으면 주소와 매도가만 정리해서 끝나지 않습니다. 의뢰인이 설명한 보증금·월세·임대차기간을 계약서와 맞춰보고, 건축물대장·등기사항전부증명서·토지이용계획·실거래와 비교해야 합니다. 전화로 의뢰받은 경우에는 빠진 정보를 확인하느라 통화가 반복되고, 특히 실제 임대현황과 계약서의 차이가 누락되기 쉬웠습니다.

Week 1에 만든 실용보드는 결과물 하나를 자동 생성하는 도구가 아니라 4주 동안 `계획 → 실행 → 검증 → DB 저장 → 다음 실험`을 이어가는 운영도구였습니다. Week 2에는 이 원리를 실제 매도 의뢰 업무에 적용해 보기로 했습니다.

## 진행 방법

### 1. 구현 전에 Plan 모드로 실제 업무를 질문했다

Codex가 바로 앱을 만들기 전에 기존 의뢰 흐름, 입력자료, 자주 누락되는 값, 결과물을 쓰는 대상과 상황을 질문했습니다. 그 결과 첫 파일럿은 실제 상가·빌딩 1건과 임대차계약서 1~5건으로 정하고, 고객용 제안서와 내부 검수표를 분리하기로 했습니다.

### 2. 원본과 자동화용 자료의 경계를 만들었다

원본 Drive 폴더에는 Codex가 접근하지 않습니다. 사람이 개인정보를 제거한 `automation-masked` 폴더만 처리하고, 페이지 누락이나 판독 실패를 추정하지 않고 상태로 남깁니다.

### 3. Skill·Plugin·MCP의 역할을 나눴다

- Skill: 근거 우선순위, 상태 구분, 고객용·내부용 출력 계약을 반복 사용
- Google Drive Plugin: 비식별 자료 폴더만 읽는 입력 통로
- 부동산·건축물대장 MCP: 현재 공식 자료 조회
- 국가법령 MCP: 용도·광고·법적 표현 쟁점이 있을 때만 조건부 조회
- Codex: 전체 실행과 충돌표·초안 작성의 중심

### 4. 충돌값을 지우지 않는 업무 화면을 만들었다

`원문 값 / 최신 조회값 / 기준일 / 확인일 / 차이 / 대표님 판단`을 나란히 기록합니다. 계약서별로 의뢰인 설명값과 실제 보증금·월세·기간을 비교하고, `자료 없음 / 추가 확인 필요 / 기준일 경과 / 불일치 / 판독 불가`를 분리합니다.

### 5. 세 번의 사람 승인 뒤에만 공개한다

입력·마스킹, 교차검증, 고객용·내부용 분리의 순서로 승인합니다. 최종 승인된 주소 없는 수치와 배운 점만 공개 실용보드에 보낼 수 있습니다.

## 결과와 배운 점

### 로컬 구현 결과

- 비공개 업무 앱과 별도 Google Sheet용 Apps Script 템플릿
- 재사용 가능한 `property-briefing` Skill
- 임대차 1~5건 대조와 합계
- 조건을 명시한 기초 임대수익률
- 3단계 승인과 Before/After 타이머
- 고객용 인쇄/PDF 분리
- 공개 보드용 비식별 허용목록
- 단위 테스트, 타입 검사, 프로덕션 빌드, 보안 감사 통과

### 실제 파일럿 후 채울 결과

- Before 활동시간: `미측정`
- After 활동시간: `미측정`
- 수정 횟수: `미측정`
- 공식 근거 수: `미측정`
- 발견한 충돌 수: `미측정`
- 추가 확인 항목 수: `미측정`

시간 단축 목표를 미리 만들지 않고 실제 결과를 그대로 기록합니다. 같은 자료로 Before를 먼저 하고 After를 실행하므로 학습효과가 있다는 한계도 함께 적습니다.

### 현재까지의 배운 점

자동화에서 가장 중요한 것은 문장을 빨리 만드는 기능보다, 어떤 자료를 믿고 어떤 충돌을 사람이 판단해야 하는지 경계를 만드는 일이었습니다. Plan 모드의 질문 과정이 그 경계를 만들었고, Goal은 앱 완성이 아니라 실제 사례 실행과 검증 증거까지 남기는 완료 기준을 유지하게 했습니다.
